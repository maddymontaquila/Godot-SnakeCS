Why this matters

Game dev is full-stack dev

Players see the game. Teams still own identity, game services, operations, platform paths, and the local loop that keeps all of it moving.

The hard part is not one service. It's running the whole stack together as you build your game.

The original Aspire "full-stack" map. Players experience the game; the team runs the whole connected system — auth, leaderboards, matchmaking, cloud saves, frontend — together. The point is the connections, not any single station.

Aspire is an agent-ready, code-first tool to compose, debug, and deploy any distributed app.

AppHost

The map.

var builder = DistributedApplication.CreateBuilder(args);

var db = builder.AddPostgres("postgres")
    .AddDatabase("scores");

var scoreApi = builder.AddCSharpApp("score-api")
    .WithReference(db);

builder.AddGoApp("matchmaking-api")
    .WithReference(scoreApi);

builder.AddNodeApp("leaderboard-api")
    .WithReference(scoreApi);

builder.AddGodotApp("godot-snake-client")
    .WithReference(scoreApi);

builder.Build().Run();
AppHost is not "more config." It is the place where the relationships are visible in code. Use the map metaphor from the existing deck, but keep implementation details verbal.
